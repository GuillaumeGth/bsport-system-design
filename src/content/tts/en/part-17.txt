There's a multi-tenant trap in rendering too. With per-studio branding, the theme has to be known before the first paint, otherwise you get a flash of unbranded content. That's a real argument for server rendering on the public surfaces, because the tokens get injected server-side. On pure client rendering, you either inline critical CSS per tenant, or accept a neutral loading screen.

And on theming itself: one build per tenant gives you optimal CSS and zero flash, but it doesn't scale. A thousand studios means a thousand builds, and a new customer waits for a deployment. The answer is a single build with CSS custom properties, with tokens resolved as early as possible.

There's an accessibility angle on theming that I think is worth raising. If a studio picks pale yellow on white, the contrast ratios collapse. So you validate contrast ratios at the moment the studio picks its colours, in the back-office, and you derive tokens automatically where you can. That link between multi-tenancy and accessibility is easy to miss.
